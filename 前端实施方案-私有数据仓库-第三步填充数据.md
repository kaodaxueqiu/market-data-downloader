ipcMain.handle('factor:myCHFillCreateConfig', async (_event, data) => {
  try {
    const apiKey = getDefaultApiKeyForMyFactor()

### 5.3 新建填充配置弹窗

**表单形式：单页长表单 + section 标题分块**（不用 el-steps 分步引导）。理由：填充配置面向进阶用户（配 SQL 列映射、JOIN、Cron），一屏看全更高效，开发量也更少。

#### Section 1：基本信息
- 配置名称（`config_name`）：`el-input`
- 目标表（`target_table`）：`el-select`，选项来自已有的表列表 `tables`
- 写入模式（`write_mode`）：`el-radio-group`
  - `append` — 增量追加（默认）
  - `overwrite` — 全量覆盖（每次清空再写）

#### Section 2：数据源配置
- 数据源类型（`source_type`）：**目前只提供 `clickhouse` 一项**（postgresql 后端字段已预留，待跨库外部表功能完成后再开放前端选项）
- 主数据源（一行）：
  - 数据库名（`database`）：`el-input`
  - 表名（`table`）：`el-input`
  - 别名（`alias`）：`el-input`（默认 `a`）

- **关联表（JOIN）**：点击 [+ 添加关联表] 动态添加行，每行结构：

```
[LEFT JOIN ▼] [数据库____] [表名____] [别名____] [ON: ________________] [×删除]
```

  - JOIN 类型：`el-select`（`LEFT JOIN` / `INNER JOIN` / `RIGHT JOIN`）
  - 数据库、表名、别名：`el-input`
  - ON 条件：`el-input`（如 `a.trade_date = b.trade_date`）
  - 可添加多个关联表

#### Section 3：列映射与过滤
- **列映射**（动态行）：
  | 源表达式（el-input） | → | 目标列（el-select） |
  |---|---|---|
  | `a.trade_date` | → | `trade_date` |
  | `a.close * b.adj` | → | `adj_close` |

  > **实现要点**：`watch(targetTable)` 监听目标表变化，自动调用 `myCHTableSchema(targetTable)` 获取列信息，填充"目标列"下拉选项。

- 增量字段（`incremental_field`）：`el-input`（可选，用于 append 模式的增量条件）
- 过滤条件（`filters`）：多行输入，每行一个 WHERE 条件
- 分组（`group_by`）：`el-select` multiple

#### Section 4：调度配置
- Cron 表达式（`schedule_cron`）：`el-input`，placeholder: `0 2 * * *`
- **Cron 快捷预设**：一组可点击的 `el-tag`，点击后自动填入 input：
  - `每天凌晨2点` → `0 2 * * *`
  - `每天凌晨5点` → `0 5 * * *`
  - `每小时` → `0 * * * *`
  - `每周一凌晨3点` → `0 3 * * 1`
- 是否立即启用调度：`el-switch`

### 5.4 任务记录弹窗

点击配置列表的"任务"按钮弹出：

| task_id | 状态 | 触发方式 | 影响行数 | 开始时间 | 完成时间 | 操作 |
|---------|------|---------|---------|---------|---------|------|
| FILL_2025... | ✅ completed | 手动 | 12,345 | ... | ... | [查看SQL] |
| FILL_2025... | 🔄 running | 定时 | - | ... | - | [取消] |
| FILL_2025... | ❌ failed | 手动 | 0 | ... | ... | [查看错误] |

状态标签映射：
- `pending` → 排队中（灰色）
- `running` → 执行中（蓝色）
- `completed` → 已完成（绿色）
- `failed` → 失败（红色）
- `cancelled` → 已取消（橙色）

### 5.5 关键交互逻辑

1. **创建配置时做 Schema 预校验**：后端创建接口会校验列映射是否匹配目标表结构，前端只需捕获错误展示即可
2. **手动执行**：点击后 `ElMessageBox.confirm` 确认（区分 overwrite 模式要警告"会清空再写"）
3. **调度开关**：`el-switch` 的 `change` 事件直接调 `myCHFillToggleSchedule`
4. **取消任务**：仅 `pending` / `running` 状态可取消
5. **删除配置**：确认弹窗，告知"关联的定时调度也会移除"

## 六、注意事项

1. **后端已就绪**：7 个接口全部已实现并编译部署，可直接联调
2. **目标表下拉**：复用已有的 `tables` 数据（即 `myCHTables` 返回的表列表），不需要额外接口
3. **目标列下拉**：`watch(targetTable)` 监听变化，自动调 `myCHTableSchema(targetTable)` 拿列信息填到目标列 select 里
4. **填充配置与建表解耦**：用户必须先建好表，才能创建填充配置（目标表下拉来自已有表）
5. **CSS 复用**：复用现有 `.cols` / `.col-row` 等样式类
6. **不需要新路由**：填充数据作为 PrivateWarehouse.vue 内的 Tab，不需要注册新路由
7. **source_type 暂只做 clickhouse**：下拉只有 `clickhouse` 一项。后端字段已预留 `postgresql`，待跨库外部表功能完成后再开放
8. **表单形式确认**：单页长表单 + section 标题分块，不用 el-steps 分步引导

## 七、接口请求/响应详细参考

### 创建填充配置 POST

请求体：
```json
{
  "config_name": "每日行情同步",
  "target_table": "daily_price",
  "source_type": "clickhouse",
  "source_config": {
    "sources": [
      { "source_type": "clickhouse", "database": "factor_data", "table": "cn_stock_daily", "alias": "a" }
    ],
    "joins": [],
    "columns": [
      { "source": "a.trade_date", "target": "trade_date" },
      { "source": "a.stock_code", "target": "stock_code" },
      { "source": "a.close", "target": "close_price" }
    ],
    "filters": ["a.trade_date >= '2020-01-01'"],
    "group_by": [],
    "incremental_field": "a.trade_date"
  },
  "write_mode": "append",
  "schedule_cron": "0 2 * * *"
}
```

响应：`{ "success": true, "message": "填充配置创建成功", "data": { "config_id": 1 } }`

### 列出配置 GET

响应：`{ "success": true, "data": [FillConfig, ...] }`

### 删除配置 DELETE

请求体：`{ "config_id": 1 }`
响应：`{ "success": true, "message": "配置已删除" }`

### 手动执行 POST

请求体：`{ "config_id": 1 }`
响应：`{ "success": true, "message": "填充任务已提交", "data": { "task_id": "FILL_20250724_abcdef12" } }`

### 查询任务 GET

可选 query: `?config_id=1`
响应：`{ "success": true, "data": [FillTask, ...] }`

### 取消任务 PUT

请求体：`{ "task_id": "FILL_20250724_abcdef12" }`
响应：`{ "success": true, "message": "任务已取消" }`

### 启停调度 POST

请求体：`{ "config_id": 1, "enabled": true }`
响应：`{ "success": true, "message": "调度已开启" }`
