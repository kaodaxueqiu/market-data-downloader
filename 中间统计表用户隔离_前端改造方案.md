# 中间统计表用户隔离 — 前端改造方案

> 日期：2026-08-04
> 优先级：高
> 关联：后端中间统计表从共享 `factor_workspace` 改为用户独立 `factor_workspace_{拼音}`

---

## 一、背景

后端已将中间统计表从全局共享库 `factor_workspace` 改为每用户独立库 `factor_workspace_{拼音}`，与私有数据仓库 `factor_mid_{拼音}` 保持一致的隔离模式。

**新增两个后端接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/v1/midstats/status` | GET | 查询当前用户的工作区库是否已初始化 |
| `/api/v1/midstats/init` | POST | 初始化工作区库（建库 + GRANT ALL 授权 + 建元数据表） |

**接口响应格式**（与私有数据仓库 `ch-status` / `ch-init` 完全一致）：

```json
// GET /api/v1/midstats/status
{
  "success": true,
  "data": {
    "initialized": false,
    "database": "factor_workspace_yuyang",
    "factor_user": "yuyang"
  }
}

// POST /api/v1/midstats/init
{
  "success": true,
  "message": "工作区库创建成功",
  "data": {
    "initialized": true,
    "database": "factor_workspace_yuyang",
    "created": true
  }
}
```

> 注：`status` 接口无论库是否已初始化都会返回 `database` 字段（拼音拼接得出，不依赖库是否存在），引导页可直接展示。

## 三、主进程改动（`src/main/index.ts`）

现有 midstats 段落起始位置为**第 6127 行**（注释 `// 中间统计表（midstats）IPC Handlers`），`MIDSTATS_API_BASE` 常量定义在第 6130 行。新增的两个 handler 应插入在 `MIDSTATS_API_BASE` 常量之后、`intermediateTable:list` handler（第 6133 行）之前。

### 3.1 状态检查

```typescript
// 检查工作区库状态
ipcMain.handle('intermediateTable:status', async () => {
  try {
    const apiKey = getDefaultApiKeyForBacktest()
    if (!apiKey) {
      return { success: false, error: '未找到API Key' }
    }
    const axios = require('axios')
    const response = await axios.get(`${MIDSTATS_API_BASE}/status`, {
      headers: { 'X-API-Key': apiKey },
      timeout: 15000
    })
    if (response.data.success) {
      return { success: true, data: response.data.data }
    } else {
      return { success: false, error: response.data.error || '检查工作区状态失败' }
    }
  } catch (error: any) {
    console.error('检查工作区库状态失败:', error.response?.status, error.response?.data || error.message)
    if (error.response?.data?.error) {
      return { success: false, error: error.response.data.error }
    }
    return { success: false, error: error.message || '网络错误' }
  }
})
```

### 3.2 初始化

```typescript
// 初始化工作区库
ipcMain.handle('intermediateTable:init', async () => {
  try {
    const apiKey = getDefaultApiKeyForBacktest()
    if (!apiKey) {
      return { success: false, error: '未找到API Key' }
    }
    const axios = require('axios')
    const response = await axios.post(`${MIDSTATS_API_BASE}/init`, {}, {
      headers: { 'X-API-Key': apiKey },
      timeout: 30000
    })
    if (response.data.success) {
      return { success: true, data: response.data.data, message: response.data.message }
    } else {
      return { success: false, error: response.data.error || '初始化工作区库失败' }
    }
  } catch (error: any) {
    console.error('初始化工作区库失败:', error.response?.data || error.message)
    if (error.response?.data?.error) {
      return { success: false, error: error.response.data.error }
    }
    return { success: false, error: error.message || '网络错误' }
  }
})
```

> 注意：
> - midstats 使用 `getDefaultApiKeyForBacktest()` 获取 API Key，与现有 5 个 handler 保持一致。
> - 返回值风格对齐现有 list handler（第 6144 行）：先判断 `response.data.success`，HTTP 200 但 body `success=false` 时把后端原始 error 透传给渲染层，避免错误信息丢失。
> - catch 块也对齐 list handler：优先取 `error.response.data.error`，兜底 `error.message`。

## 四、Preload 改动（`src/preload/index.ts`）

### 4.1 桥接方法（约第 304 行）

在 `intermediateTable` 对象中新增 `status` 和 `init`：

```typescript
intermediateTable: {
  status: () => ipcRenderer.invoke('intermediateTable:status'),
  init: () => ipcRenderer.invoke('intermediateTable:init'),
  list: () => ipcRenderer.invoke('intermediateTable:list'),
  create: (data: any) => ipcRenderer.invoke('intermediateTable:create', data),
  delete: (tableName: string) => ipcRenderer.invoke('intermediateTable:delete', tableName),
  update: (tableName: string, data: any) => ipcRenderer.invoke('intermediateTable:update', tableName, data),
  setTtl: (tableName: string, ttl: string) => ipcRenderer.invoke('intermediateTable:setTtl', tableName, ttl)
},
```

### 4.2 类型声明（约第 909 行）

```typescript
intermediateTable: {
  status: () => Promise<any>
  init: () => Promise<any>
  list: () => Promise<any>
  create: (data: any) => Promise<any>
  delete: (tableName: string) => Promise<any>
  update: (tableName: string, data: any) => Promise<any>
  setTtl: (tableName: string, ttl: string) => Promise<any>
}
```

## 五、渲染层改动（`ListContent.vue`）

### 5.1 模板改动 — 四态分支

相比私有数据仓库的三态，这里增加了**接口错误态**，避免网络异常时用户误点初始化：

```html
<template>
  <div class="list-content">
    <!-- 1. 加载中 -->
    <div v-if="pageLoading" class="loading-wrap">
      <el-icon class="is-loading" :size="32"><Loading /></el-icon>
    </div>

    <!-- 2. 接口错误：重试页（网络异常等） -->
    <div v-else-if="initError" class="init-container">
      <div class="init-card">
        <p class="init-desc">无法连接服务器，请检查网络后重试</p>
        <el-button type="primary" @click="checkStatus">重新检查</el-button>
      </div>
    </div>

    <!-- 3. 确未初始化：引导页 -->
    <div v-else-if="!isInitialized" class="init-container">
      <div class="init-card">
```

### 5.2 Script 改动

```typescript

const isInitialized = ref(false)
const initError = ref(false)   // 接口调用失败（网络异常等），区别于"确未初始化"

const ttlVisible = ref(false)
const ttlRow = ref<IntermediateTableMeta | null>(null)

// === 新增：检查状态 ===
const checkStatus = async () => {
  pageLoading.value = true
  initError.value = false
  try {
    const result = await window.electronAPI.intermediateTable.status()
    if (result.success && result.data) {

  } finally {
    pageLoading.value = false
  }
}

  initLoading.value = true

    }

    ElMessage.error(e.message || '初始化失败')
  } finally {
    initLoading.value = false
  }
}

```

> **错误兜底说明**：私有数据仓库（PrivateWarehouse.vue）的 `checkStatus` 在接口失败时 `isInitialized` 保持 `false`，页面会卡在引导页，用户可能误点初始化。本方案新增 `initError` 状态区分"接口失败"和"确未初始化"：
> - `initError = true` → 显示"无法连接服务器"重试页
> - `initError = false, isInitialized = false` → 显示初始化引导页
> - `initError = false, isInitialized = true` → 显示列表

## 六、交互流程

```
用户进入中间统计表页面
      │
      ▼
  checkStatus()  (pageLoading=true → 显示 Loading)
      │
      ▼
  调 GET /api/v1/midstats/status
      │
      ├── 接口失败/网络异常 → initError=true → 显示"无法连接"重试页
      │        │
      │        ▼ 用户点"重新检查"
      │    checkStatus() 重试
      │
      ├── initialized=false → 显示引导页（初始化按钮）
      │        │
      │        ▼ 用户点击"初始化工作区"
      │    调 POST /api/v1/midstats/init
      │        │
      │        ├── 成功 → checkStatus() → 显示列表
      │        └── 失败 → ElMessage.error
      │
      └── initialized=true → loadList() → 显示表列表
                                   │
                                   └── 列表为空 → 沿用现有空表格提示
                                        "暂无中间统计表，点击右上角「新建」创建"
```

## 七、注意事项

1. **表名变更**：后端返回的 `full_name` 从 `factor_workspace.it_xxx` 变为 `factor_workspace_{拼音}.it_xxx`，前端直接用 `full_name` 字段即可，不需要硬编码库名。

2. **API Key**：midstats 使用 `getDefaultApiKeyForBacktest()`，与现有 handler 一致，不需要改。

3. **空列表处理**：初始化后如果没有任何表，沿用现有的 `<template #empty>` 空提示即可（"暂无中间统计表，点击右上角「新建」创建"），不需要额外的空状态引导页。

4. **图标引入**：`Coin` 图标在项目中已广泛使用（DataCenter、PrivateWarehouse、EngineConfig、CacheManager 等 7 个文件），`element-plus/icons-vue` 确认有导出，可直接引入。`Loading` 同理。

5. **未初始化时的后端错误**：如果用户跳过初始化直接调 list/create 等接口，后端会返回 400 错误："工作区库尚未初始化，请先调用 init 接口创建库"。前端四态引导页已避免此情况。

6. **不影响现有功能**：Create/Delete/Update/SetTTL 的调用方式不变，只是增加了初始化前置步骤。

7. **与私有数据仓库的差异**：私有数据仓库的 `checkStatus` 在接口失败时会误显示引导页；本方案通过 `initError` 状态解决了这个问题。如果后续私有数据仓库也想改进，可参考本方案的错误兜底逻辑。

8. **import 合并**：`ListContent.vue` 现有 import 行（第 93 行）为 `import { Refresh, Plus } from '@element-plus/icons-vue'`，改造时需要把 `Loading, Coin` 追加到同一行，不能直接覆盖，避免丢失原有图标引用。方案 5.2 已注明合并方式。

9. **dbStatus 兼容**：引导页中 `v-if="dbStatus"` 展示库名 tag，如果后端未返回 `database` 字段，tag 不显示但不会报错，兼容无问题。
